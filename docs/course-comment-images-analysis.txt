2. post 댓글 이미지 구현과의 차이
=====================================================================

동일해서 그대로 옮길 수 있는 부분
- 2단 답글 구조(parent + replyTo), 소프트 삭제, content_moderations 기반 조치/복구
- Mapper/Service/Controller 메서드 시그니처와 흐름
- 목록 SQL 이 삭제/조치 댓글 행을 placeholder 로 내려주는 방식(content/nickname 을 SQL 에서 NULL 처리)
- 프런트가 비모듈 IIFE + createElement 렌더링
- 페이지네이션(size 5), 정렬(latest/oldest/likes), deep link(location) 구조

코스 쪽만 다른 점 (주의 필요)
(1) 컬럼명 create_at (post 는 created_at) → 새 테이블에는 영향 없지만 조인/정렬 쿼리 작성 시 주의
(2) course_comments 에 레거시 image_url 컬럼이 남아 있음
    → 재사용하지 말고 course_comment_images 만 사용 (destination 이 같은 방식으로 정리됨).
      모델 CourseComment.imageUrl 도 사용처가 없으므로 이번 작업에서 건드리지 않거나
      마지막에 별도 정리 단계로 두는 것을 권장.
(3) CourseCommentDto 에는 @JsonInclude(NON_NULL) 이 없어 필드가 항상 직렬화됨
    → imageUrls 기본값 List.of() 로 두면 항상 [] 로 내려감(프런트 분기 단순, post 와 동일 결과)
(4) 코스 상세는 comment.css 를 로드하지 않고 content-comment.css 만 로드
    → 썸네일/미리보기/모달 CSS 를 course-detail.css 에 .course-comments 스코프로 추가해야 함
      (post 는 post-detail.css 에 .post-comments 스코프로 넣어둠)
(5) 업로드 하위 경로는 post-comments 와 섞이지 않게 course-comments 로 분리 필요
(6) 코스 댓글 작성폼은 아직 카드형이 아님(질문/팁 댓글은 카드형으로 통일 완료)

post 에서 확립된 정책(그대로 적용 대상)
- MAX_COMMENT_IMAGES = 3, 실제 비어 있지 않은 파일만 카운트, 초과 시 요청 전체 거부
- 공용 service/comment/CommentImageLimitException 재사용, 400 {"message": "..."} 응답
- FileUploadService.saveFile(file, "<subdir>") 로 저장(기존 정책 그대로, 새 검증 규칙 추가 안 함)
- 댓글 insert → id 확보 → display_order 1,2,3 저장, 실패 시 이번 요청 파일만 정리
- 읽기: 삭제되지 않은 commentId 만 모아 findByCommentIds 1회 호출 후 groupingBy → N+1 없음
- 삭제/조치 댓글은 imageUrls 빈 목록, 이미지 행은 유지 → 복구 시 자동 재노출
- 프런트: selected[] + DataTransfer 누적, 중복(name|size|lastModified) 방지, 미리보기 + 개별 X,
  비면 미리보기 숨김, 댓글/답글 모두 첨부, 본문 아래 1~3장 렌더, 클릭 확대 모달(좌우 순환,
  ArrowLeft/ArrowRight, ESC/backdrop/이미지 클릭 닫기, 1장이면 좌우 버튼 숨김)

3. course_comment_images CREATE TABLE SQL (제안 / 미실행)
=====================================================================

course_comments.id 가 bigint, 테이블 charset 이 utf8mb3 이므로
post_comment_images / destination_comment_images 와 동일 규격으로 맞춘다.

CREATE TABLE `course_comment_images` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `comment_id` bigint NOT NULL,
  `image_url` varchar(255) NOT NULL,
  `display_order` int NOT NULL DEFAULT '1',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uq_course_comment_images_order` (`comment_id`,`display_order`),
  CONSTRAINT `fk_course_comment_images_comment`
    FOREIGN KEY (`comment_id`) REFERENCES `course_comments` (`id`) ON DELETE CASCADE,
  CONSTRAINT `chk_course_comment_images_order`
    CHECK (((`display_order` >= 1) and (`display_order` <= 3)))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb3;

- post_comment_images 와 합치지 않는다(요청 사항). 세 테이블은 각 댓글 테이블에 1:1 대응.
- comment_id 는 UNIQUE KEY 선두 컬럼이라 별도 조회 인덱스 불필요.
- course_comments 에는 어떤 컬럼도 추가하지 않는다(레거시 image_url 도 그대로 방치).
- 소프트 삭제/조치 시 이미지 행 유지 → 복구하면 그대로 다시 노출.

5. 단계별 구현 순서 (제안)
=====================================================================

STEP 1. DB
  - course_comment_images CREATE TABLE 실행(사용자) + 스키마 문서 반영
STEP 2. 영속 계층만
  - CourseCommentImage 모델 + Mapper 인터페이스 + XML(insert, findByCommentIds:
    빈 목록이면 1=0 가드, ORDER BY comment_id, display_order) + mapper 계약 테스트
    → 이 단계까지 기존 동작 변화 없음
STEP 3. 읽기 경로
  - CourseCommentDto.imageUrls 추가
  - Service 의 목록/페이징/단건(findDtoById) 결과에 attachImageUrls() 로 일괄 주입
  - 삭제/조치 댓글은 조회 대상에서 제외 → 빈 목록
STEP 4. 쓰기 경로
  - Controller multipart 전환 + Service 3장 검증/파일 저장(FileUploadService, subdir "course-comments")
    /display_order 저장/실패 시 이번 요청 파일 정리
  - 기존 컨트롤러·시큐리티 테스트 수정
  - (중간 상태: 프런트가 아직 JSON 이라 브라우저 등록은 415 → STEP 5 에서 해소)
STEP 5. 사진 선택/미리보기/multipart 전송
  - detail.html 폼에 파일 input + 미리보기, course-comments.js 에 picker/FormData
  - 답글 폼에도 동일 적용
STEP 6. 댓글 이미지 렌더링
  - renderComment 에 makeCommentImages 추가(본문 아래, 액션 위), 삭제/조치 댓글은 미노출
STEP 7. 확대 모달
  - detail.html 모달 마크업 + course-comments.js initCommentImageModal + CSS
STEP 8. 댓글 작성폼 디자인 통일 (별도 단계)
  - .course-comment-form 을 카드형으로, 사진 버튼/미리보기 규격을 질문/팁과 동일하게

순서 타당성: STEP 2~3 은 화면 변화가 없어 안전하게 선반영 가능하고,
STEP 4 만 단독 배포 시 등록이 깨지므로 STEP 4~5 는 연달아 진행하는 것을 권장.
STEP 8 은 기능과 독립적이므로 마지막에 두거나 STEP 5 와 함께 처리해도 됨.
